# SentinelGuard Hardened Image Runbook

> **Historical reference — superseded for release decisions.** This records an earlier design, operation, or validation attempt. It is not the current architecture, a supported quick start, or evidence that the source preview is production ready. Start with the repository README and current documentation index.


Purpose: build hardened images with Packer, optionally embedding the SentinelGuard (Go) agent plus Wazuh-sidecar integration, while keeping the build reproducible and provably clean.

## Toggle: include or skip SentinelGuard
- Flag: `sentinel_guard_enabled` (bool). Default `true`. Set to `false` to produce a hardened image without the agent.
- Version: `sentinel_guard_version` (tag/commit of the agent build artifact).
- Artifact: `sentinel_guard_package` (path/URL to the signed tar/zip that contains the SentinelGuard binary, config template, systemd/launchd service files, and bundled Wazuh agent where applicable). Use tarballs generated by `SentinelGuard/build/package-agents.sh` (e.g., `artifacts/edr-agent/<version>/sentinelguard-agent-linux-amd64-<version>.tar.gz`).

## Packer inputs to add (per template)
- Common vars: `sentinel_guard_enabled`, `sentinel_guard_version`, `sentinel_guard_package`, `tenant_id`, `ingest_url`, `agent_id` (or allow empty and let runtime generate), `tls_verify` (default `true`), `auth_token` (empty; inject at deploy time, not baked).
- File provisioners:
  - Upload the signed SentinelGuard package to a staging path (e.g., `/tmp/sentinelguard.tgz`).
  - Upload a config template (e.g., `/tmp/sentinelguard.config.tmpl` with `tenant_id`, `ingest_url`, `agent_id`, `tls_verify` placeholders and Wazuh alert path).
- Shell/Ansible provisioners (gated by `sentinel_guard_enabled`):
  - Install package dependencies (systemd/launchd service helpers).
  - Install Wazuh agent if not already present; set it to emit JSON alerts (e.g., `alerts.json`) readable by SentinelGuard.
  - Install SentinelGuard into `/opt/sentinelguard`, drop config to `/etc/sentinelguard/config.yaml`, and enable service.
  - Do not bake secrets; keep `auth_token` empty or sourced from runtime secrets management.
- OS variants:
  - Linux: deb/rpm targets (amd64/arm64) with systemd unit.
  - macOS: pkg with launchd plist.
  - Windows: MSI with service install; ensure Event Log read permissions if consuming Wazuh output there.

## Build flow (per image type)
1) Build SentinelGuard artifact (CI/local): `./SentinelGuard/build/build-matrix.sh` then `AGENT_VERSION=<tag> ./SentinelGuard/build/package-agents.sh` → produces cross-OS tarballs in `artifacts/edr-agent/<version>/` with checksums; generate SBOM and AV scan as part of the job.
2) Publish artifact to an internal bucket/registry or GitHub Release with immutable tag `sentinel_guard_version`; record hash/signature for consumption by Packer.
3) Run Packer:
   - Example: `packer build -var-file=env/dev.pkrvars.hcl -var 'sentinel_guard_enabled=true' packer/templates/<image>.pkr.hcl`
   - To skip agent: same command with `-var 'sentinel_guard_enabled=false'`.
4) Hardening steps run as usual (CIS, updates, auditd/logging).
5) Post-provision validation (conditioned on `sentinel_guard_enabled=true`):
   - Check binary hash against supplied checksum.
   - Ensure service enabled + started (`systemctl status sentinelguard` or platform equivalent).
   - Validate config rendering contains `tenant_id` and `ingest_url`; `auth_token` remains blank.
   - Confirm Wazuh output file/socket is present and readable by sentinelguard user/group.
   - Run `packer/scripts/validate-sentinelguard-install.sh` on the baked image to assert binary, config, and service unit are present.

## Runtime configuration expectations
- Config file: `/etc/sentinelguard/config.yaml`
  - Required: `tenant_id`, `ingest_url`
  - Recommended: `agent_id` (stable host identifier), `tls_verify`, `wazuh_alert_path`
  - Runtime secret injection: `auth_token` (from secret store or user data), optional mTLS materials if used.
- Service account: run as least-privilege user `sentinelguard`; grant read access to Wazuh alert output only.
- Networking: outbound HTTPS to the ingest endpoint; no inbound listeners exposed by default.

## Quality and cleanliness gates
- Sign all artifacts (Authenticode/Apple codesign/mac notarization/GPG for Linux repos).
- Generate SBOM and supply-chain attestations per build; retain hashes in release metadata.
- AV/EDR scan the packaged artifact and the baked image; fail the build on detections.
- Keep a build log of provenance (Packer template version, agent version, Wazuh version).

## Minimal-friction install goal
- One-click/quiet builds for customers: expose a single toggle to include SentinelGuard; keep all branding as “SentinelGuard.”
- Clear uninstall/disable path: provide a `sentinelguard-uninstall` script and allow `sentinel_guard_enabled=false` builds for customers that opt out.
